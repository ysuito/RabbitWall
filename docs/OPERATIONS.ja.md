# 日常運用

[English](OPERATIONS.md) | [日本語](OPERATIONS.ja.md)

## 画面

- **観**：通信マップ、経路一覧、監視ノード、AI側の対外接続トグル。
- **覧**：現在の接続、観測履歴、Firewallの拒否ログ。IP・ドメイン・ポート・国・状態で検索できる。
- **析**：通信量ランキングと初めて観測したドメイン。
- **設**：配色と国別IPデータの状態。

セッションは約5秒ごと、ノードのPingは約10秒ごとに確認する。観測の間に完結する短い通信は表示されない場合がある。地図のアニメーションは接続の存在を表し、パケット数や速度を示すものではない。

「正」は正常、「断」はPing応答なし、「不」は確認不能、「古」は監視データの更新停止。Pingに応答しない設定の端末は、稼働中でも「断」と表示される。

地図上のホイール操作で、カーソル位置を中心に1〜6倍まで拡大・縮小できます。LANの配置図と文字、通信経路も一緒に拡大します。ドラッグで移動し、「初期表示」で倍率と位置を戻せます。Ctrl／Commandを押しながらの操作はブラウザー側に任せます。

## 対外接続の開閉

管理PCのmTLS接続でトグルを操作する。再起動・制御サービスの再起動・導入・更新直後は「閉」。開状態は制御プロセスが更新する20秒のカーネル許可期限で管理する。更新が途絶えると期限切れで閉じる。

**1分・5分・30分**ボタンで指定時間だけ開通し、期限になるとDNS・既存の対外通信も含めて自動遮断します。残り時間は対外接続パネルに表示します。期限は制御プロセスとカーネルの許可期限で管理するため、ブラウザを閉じても有効です。時限ボタンを再度押すと、その時点から期限を設定し直します。トグルでいつでも即時遮断でき、トグルで開く場合は時間制限なしです。再起動・制御サービス再起動後はタイマーを引き継がず「閉」になります。

「閉」ではAI側からの外向き通信、処理中の通信と戻り、DNS受付・転送・応答を遮断する。管理SSH・監視Ping・RabbitWall自身の更新用通信は維持する。開状態でも、許可するのは基本FWの範囲内（公開IPv4へのTCP80/443・UDP123、RabbitWall経由のDNS）の通信に限る。

## ノードの追加・編集・削除

管理PCから証明書付きHTTPSで接続し、**設 → ノード管理**を開きます。名前・IPv4アドレス・AI側／上流側を設定し、**死活監視**、**管理PCからSSH**、**管理PCからPing**をそれぞれ選択して「保存して反映」を押します。登録上限は上流側を含め12件で、全件削除も可能です。新しく追加したノードの管理アクセスは初期状態では許可しません。SSH・Pingの許可はAI側ノードのみが対象です。

監視を無効にすると主要ノードは「休」と表示します。監視の有無は管理アクセスの許可に影響しません。ノードを削除してもAI側サブネット全体の通信観測とDNS受付は継続します。地図の表示名・配置も保存後に更新します。上限を超える地図ノードはまとめて表示します。

保存はノード情報と専用Firewallルールだけを更新します。NIC・DNS・対外接続の開閉状態は変更せず、サービス再起動も不要です。管理アクセスを無効化・削除したノードへの既存SSH接続も遮断します。別画面からの同時編集は検出して上書きを拒否するため、再読み込みして編集し直してください。入力エラー時は変更しません。保存失敗時は元の設定とルールへの復元を試み、適用処理に失敗した場合は対外接続を閉じます。

初期ノードは `/etc/rabbitwall.json` の `nodes` です。画面から保存したノード情報は `/etc/rabbitwall-nodes/nodes.json` に保存され、初期ノードに優先します。`setup.py update` と再起動後も保持します。保存前の設定は `/etc/rabbitwall-nodes/node-backups/` に保存します。バックアップでは両方のJSONを保管してください。

`setup.py reconfigure --config rabbitwall.json --apply-network` は指定JSONを正として全ネットワークを再適用し、画面で保存したノード情報もリセットします。必要なノードを先に入力JSONへ転記してください。JSONで指定できる各ノードの追加項目は `monitor`・`allow_ssh`・`allow_ping`（boolean）です。省略時は監視が有効で、AI側ノードへの管理SSH・Pingも許可されるため、JSONを直接編集するときは明示してください。

## DNSと推定ドメイン

AI端末は `ai_cidr` のホストIPをDNSとゲートウェイに設定する。Unbound（`rabbitwall-dns.service`）が `dns_upstream` へUDP/TCP53で問い合わせ、結果をキャッシュする。AI端末から上流や外部DNSへの直接の53番通信は拒否する。

独立した `rabbitwall-dns-observer.service` がUnboundの端末向け応答をdnstapのUnixソケットから受信する。同じ端末へのA/AAAAの正の応答と通信先IPを照合し、「推定ドメイン」として表示する。CNAMEは問い合わせた元の名前を表示し、有効期限には経路中の短いTTLを使う（上限1時間）。共有IPに複数の名前が対応する場合は候補を併記する。HTTPSのホスト名やURLを確定する機能ではない。Unboundのキャッシュ応答も残りTTLで照合する。DoH、端末自身のキャッシュだけを使う通信、IP直指定などは照合できないことがある。

観測情報は `/run/rabbitwall-dns/observations.json` に最大1万件、メモリ上の一時ファイルとして保存する。再起動で消える。DNSパケットや問い合わせごとのディスクログは保存しない。セッションに付いた候補名は、そのセッション履歴と一緒に保存する。

観測サービスが停止・再起動してもUnboundは継続し、開状態のDNSは利用できる。観測が遅れる場合はイベントが欠落することがある。停止中のイベントの一部はバッファから遅れて届くが、欠落したイベントは復元できない。既存セッションの候補は履歴に残るが、新しい候補は観測再開後のDNS応答から追加する。「閉」のDNS遮断は観測サービスに依存せず、Unboundのキャッシュ応答も含めてカーネルで行う。

上流は設定されたDNSだけを使用し、失敗時に直接再帰問い合わせへ切り替えない。現構成ではUnbound自身のDNSSEC検証・上流DNSの暗号化は有効にしない。

## 初めてのドメイン

DNS応答で初めて観測した問い合わせ名を台帳へ登録し、24時間「新」を表示する。導入直後は普段利用するドメインも新着になる。名前は大文字小文字を区別せず、サブドメインは別の名前として扱う。

既知ドメインは再起動後も記憶する。上限は10万件。上限に達すると新規登録を停止し、画面に表示する。新着一覧は直近100件まで表示する。DNS応答の観測は、その名前への接続成立を示すものではない。

## 通信量ランキング

AI側から公開IPv4への通信を、直近1時間／24時間、宛先IP／推定ドメイン、送信／受信／合計で集計する。上位20件を表示する。管理SSH、RabbitWall自身の通信、ローカルDNSは対象外。

conntrackの累計カウンターから約5秒ごとに増分を採取し、1分単位で保存する。同じ累計値を繰り返し加算しない。最初の観測は基準値とし、カウンター減少や30秒超の収集停止後も基準値を取り直す。

候補が1つなら同じ名前の複数IPをまとめる。複数候補の通信は各候補へ重複加算せず、IP単位の「複数候補」にまとめる。最初の観測まで、最終観測後、収集停止中、観測間に終了した接続の通信量は含まれない。課金用途の厳密な計測ではない。

## 保存と容量

セッション履歴・既知ドメイン・通信量は `/var/lib/rabbitwall/history.sqlite3` に保存する。終了済みセッションは24時間、全体の目安は2万件。通信量は過去24時間分。既知ドメイン台帳にはこの履歴期限を適用しない。DBは収集トランザクションごとに更新するため、ストレージの空き容量と書き込み量を運用環境で確認する。

拒否ログはカーネルのjournalから直近5分・最大200件を表示する。FWのログレート制限や、ログを出さないルールによる拒否は含まれず、拒否パケットの総数ではない。

## 国別IPデータ

RabbitWall上で実行する。

```sh
sudo python3 /opt/rabbitwall/update_geoip.py
```

IPと国の照合はローカルで行い、通信先IPを外部へ送信しない。データの出典・ライセンスは [第三者資材](../src/rabbitwall/static/THIRD_PARTY.md) を参照。国は概算で、VPN・CDNなどの実際の利用者所在地とは異なる場合がある。

## バックアップと切り分け

```sh
sudo python3 setup.py doctor
sudo journalctl -u rabbitwall-control -u rabbitwall-dns -u rabbitwall-dns-observer -u rabbitwall-collector -u rabbitwall-caddy -n 60 --no-pager
sudo nft list table inet rabbitwall_console
```

DBをバックアップする場合はSQLiteのバックアップ機能を使うか、collectorを停止してからコピーする。設定・証明書・通信履歴を含むバックアップは公開リポジトリへ入れない。証明書の登録・更新と導入時の復旧は [導入ガイド](INSTALL.ja.md) を参照。

IP・IF・ゲートウェイ・NAT・DNS設定の訂正は、RabbitWall導入先PCのローカルコンソールで `setup.py reconfigure --config rabbitwall.json --apply-network` を使います。アプリ更新も含み、`update` だけではネットワーク設定は反映されません。[導入ガイド](INSTALL.ja.md) の「IP設定の訂正と再適用」を参照してください。
